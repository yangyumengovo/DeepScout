> 离线演示语料（示意性技术综述，供 mock 模式使用）

KV Cache 是自回归推理加速的关键：缓存已生成 token 的 Key/Value 投影，避免每步重算。但它的显存占用与序列长度、层数、KV 头数成正比，长上下文场景下常常成为比算力更早撞到的墙——一个典型的中等规模模型在数十万 token 的上下文下，仅 KV 缓存就可能占用数十 GB 显存。

KV 压缩的三类主要手段：量化把 KV 从 16 位压到 8 位甚至 4 位，精度损失通常可控；淘汰类方法（如 H2O、SnapKV）基于注意力得分识别重要 token，丢弃或合并其余位置的缓存，把缓存控制在固定预算内；共享与复用类方法利用前缀共享（系统提示词、few-shot 前缀在多请求间共享）与跨层共享降低冗余。工程上，PagedAttention 式分页管理是这些手段的载体。

对 Agent 应用而言，KV Cache 的意义不止于成本：多轮对话与工具调用循环都会复用长前缀，前缀缓存命中率直接决定响应延迟。评估长上下文方案的部署成本时，应同时统计首 token 延迟、吞吐与每百万 token 服务成本，而不是只看模型榜单分数。
